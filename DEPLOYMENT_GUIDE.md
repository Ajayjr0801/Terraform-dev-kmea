## Step-by-Step Deployment

### Phase 1: Bootstrap (One-Time Setup)

This creates the S3 bucket and DynamoDB table where Terraform will store its state.

```bash
cd bootstrap
terraform init
terraform apply
cd ..
```

**What gets created:**
- `kmea-dev-tfstate-ap-south-1` S3 bucket (state storage)
- `kmea-dev-tflock` DynamoDB table (state locking)

---

### Phase 2: Initialize Dev Environment

```bash
cd environments/dev
terraform init
```

This downloads all necessary providers and modules.

---

### Phase 3: Review Plan (RECOMMENDED)

```bash
terraform plan -var-file=terraform.tfvars
```

Review the output to see exactly what will be created before applying.

---

### Phase 4: Apply Infrastructure

```bash
terraform apply -var-file=terraform.tfvars
```

Type `yes` when prompted. This will create all AWS resources.

**Typical creation time:** 15-25 minutes

## Important Configuration Notes

### Jumphost Access
- **SSH:** Currently DISABLED (empty CIDR list)
  - Add your IP: `jumphost_allowed_ssh_cidrs = ["YOUR_IP/32"]`
  - Also set: `jumphost_key_name = "your-ec2-keypair"`
  
- **SSM Session Manager:** Always available
  ```bash
  aws ssm start-session --target <instance-id> --region ap-south-1
  ```

### RDS Password
- Auto-generated by AWS Secrets Manager
- Retrieve via: `terraform output rds_secret_arn`
- Access from: AWS Secrets Manager console

### S3 Buckets
- All private (not public)
- Access via CloudFront CDNs only
- SPA routing enabled (404/403 → /index.html)

### EKS Access
- Private API endpoint only
- Access from jumphost or within VPC
  ```bash
  aws eks update-kubeconfig \
    --name kmea-dev-eks \
    --region ap-south-1
  ```

### API Gateway (Manual)
- Not managed by Terraform
- Create REST API in AWS Console
- Connect to internal ALB via VPC Link
- Update ALB security group for VPC Link ENI traffic

## Troubleshooting

### Bootstrap fails with bucket already exists
```bash
# The S3 bucket already exists (maybe from previous run)
# Either:
# 1. Use a different bucket name in bootstrap/main.tf
# 2. Or destroy and recreate the backend
aws s3 rm s3://kmea-dev-tfstate-ap-south-1 --recursive
```

### Provider initialization fails
```bash
# Clear cache and retry
rm -rf .terraform
terraform init
```

### RDS DNS not resolving in EKS
- Ensure RDS is in private subnets (it is)
- Security group allows traffic from EKS node SG ✓
- Wait 5-10 minutes for DNS propagation

### EKS API not accessible
- Ensure you're calling from jumphost or within VPC
- Check security group allows port 443 from your source
